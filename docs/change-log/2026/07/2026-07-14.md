- 재현: HOP에서 기존 표준 파일을 직접 열어 활동 셀 겹침과 비표준 줄 정보 안내를 확인했다. PDF 첫 페이지는 `수업 개요 2열`과 `교수·학습 과정 4열` 구조임을 대조했다.
- 반영: 표준 HWPX를 PDF와 같은 `수업 개요 2열`, `교수·학습 과정 4열`, `과정중심평가 4열`, `지원·성찰·후속 학습 1열 표`로 바꿨다. PDF 열 비율을 HWPX 전체 너비에 환산해 적용했다.

- 사용성: 다운로드 선택지 이름을 `한글 HWPX (PDF형 정식 표)`와 `간편 HWPX (호환성 우선 · 2열)`로 구분해 두 형식의 목적을 명확히 했다.
- 검수: 두 HWPX 스킬의 구조 검사에서 모두 `VALID`, 네임스페이스 수정 0건, 최종화 `PASS`, 레이아웃 경고 0건, 필수 내용 검사 통과를 확인했다. 같은 데이터의 PDF와 HWPX 비교용 샘플을 새로 생성했다.

## 16:24 KST · 수업·평가 설계 · 융합수업·TPACK·SAMR·GRASPS 추가

- 요청: 융합수업, TPACK, SAMR, GRASPS를 교사가 선택할 수 있는 설계 방식으로 추가한다.
- 분류: 융합수업은 `융합 수업 설계`, TPACK과 SAMR은 `에듀테크 설계`로 지도안 단계에 추가했다. TPACK과 SAMR은 시간 순서형 수업 모형이 아니라 기술 활용을 선택·점검하는 설계 틀임을 화면에서 함께 안내한다.
- 생성 반영: 각 설계마다 교사 활동, 학생 증거, 피해야 할 흐름과 공식 참고 자료를 로컬 가이드로 만들고 지도안 생성 프롬프트와 검증에 연결했다.
- 생성 구분: 융합수업은 도입-전개-정리의 수업 흐름으로 반영하되, TPACK·SAMR은 시간 순서에 끼워 넣지 않는다. 각 차시 전체의 `설계 점검`으로 생성하고 순서와 무관하게 검증한다. SAMR은 대체(S)·증강(A)·수정(M)·재정의(R)의 네 수준 중 학습 목표에 맞는 수준을 1개 이상 선택하고, `선택 이유`와 `과제 변화`를 남기도록 했다.
- 학습지 연결: 융합수업에는 `융합 연결·적용지`, TPACK·SAMR에는 `에듀테크 학습 확인·적용지`를 추천하도록 연결했다.
- 수행평가: 기존 실제적 수행과제를 `GRASPS 실제적 수행과제`로 명확히 하고, 목표(G)·역할(R)·청중(A)·상황(S)·산출물(P)·성공 기준(S)의 여섯 요소를 화면 설명과 생성 프롬프트에 반영했다.
- GRASPS 데이터 연결: 목표(G)와 성공 기준(S)을 생성 스키마, 교사 편집 화면, 로컬 저장, 학생용 안내 표지, PDF·HWPX 내보내기까지 보존한다. 기존에 저장된 평가는 전이 목표와 교사가 입력한 성공 증거를 이용해 두 항목을 채운다.
- 용어 연결: 지도안 선택 단계는 `수업 설계`로 통합하되, 생성 요약·완성 지도안·학습지·내보내기에서는 융합수업 등은 `수업 모형`, TPACK·SAMR은 `설계 틀`로 구분한다. 설계 틀을 선택한 학습지 프롬프트에는 점검 항목을 수업 단계나 문항 순서로 복사하지 말고 실제 학생 활동으로 바꾸도록 명시했다.
- 사용성: 좁은 화면에서도 쉬운 설명의 의미 단위를 함께 줄바꿈해 낱말이 홀로 남지 않게 했다. 순차 수업 모형은 화살표, TPACK·SAMR 점검 기준과 GRASPS 여섯 요소는 가운데점으로 구분한다. GRASPS를 선택한 경우에만 편집기에 G·R·A·S·P·S 문자를 표시한다.
- 검증: 신규 분류, 선택 화면, 가이드·출처 문서, 학습지 추천, 설계 점검 검증, GRASPS 생성·편집·저장·내보내기 관련 회귀 테스트를 포함한 전체 Vitest 92개 파일·799개 테스트를 통과했다. Next.js 프로덕션 빌드가 성공했고, 실제 프로덕션 브라우저에서 375·768·1280px의 선택·설명 동작과 가로 넘침 없음, 개발용 오버레이 미노출을 확인했다.
