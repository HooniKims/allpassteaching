# 수업 지도안 수정 1차 설계

## 작성 정보

- 작성 시각: 2026년 7월 11일 20:27 KST
- 대상: 표준 교수·학습 과정안 MVP
- 확정 접근법: B안 · 생성 입력 스냅샷

## 목표

교사가 생성 전 입력을 언제든 다시 확인·수정하고, 변경한 입력으로 지도안을 반복 생성할 수 있게 한다. 날짜와 교시, 직접 입력 과목, 수업 모형의 교수·학습 절차를 생성 결과와 모든 내보내기 형식에 일관되게 반영한다. HWPX의 표 잘림과 찌그러짐을 해결하고, 이번 요청부터 변경 이력을 날짜·시각·종류별 Markdown으로 축적한다.

## 사용자 요청 범위

1. 완성 지도안 개요 표의 `일시`부터 `수업 모형`까지 제목과 값을 가운데 정렬한다.
2. `datetime-local`이 만든 `T`와 현재 시각을 없애고, 수업 정보 단계에서 교시를 입력한다.
3. 생성 뒤에도 수업 정보, 성취기준, 수업 모형 선택을 확인한다.
4. 이전 단계에서 내용을 수정한 뒤 같은 작업 안에서 다시 생성한다.
5. HWPX에서 도입·전개·정리 병합 셀과 표 내용이 잘리거나 찌그러지는 문제를 고친다.
6. 선택한 수업 모형이 실제 교수·학생 활동에 반영되는지 모형별로 점검하고, 근거 자료를 로컬 Markdown 가이드로 제공한다.
7. `2022_Revised_National_Curriculum 복사본`에서 `복사본`을 지운 새 폴더명을 앱 전체에서 사용한다.
8. 공식 과목 목록 외에 직접 과목을 입력하고, 관련 공식 과목과 성취기준을 AI로 찾는다.
9. 요청과 실제 수정 결과를 월·일·시각 및 종류별로 기록한다.

## 확정된 사용자 경험

### 생성 후 확인과 단계 이동

승인된 A안인 `요약 카드 + 자유로운 단계 이동`을 사용한다.

- 완성 화면 상단에 학교급, 학년, 표시 과목, 날짜, 교시, 차시, 선택 성취기준, 수업 모형을 요약한다.
- 왼쪽 단계 탐색에서 완료했거나 현재 도달한 단계를 버튼으로 선택할 수 있다.
- 이전 단계로 이동해도 생성된 지도안과 교사의 편집 내용은 즉시 삭제하지 않는다.
- 완성 화면으로 돌아오면 현재 입력과 마지막 생성 입력 스냅샷을 비교한다.
- 입력이 바뀌었으면 `현재 지도안은 변경 전 입력으로 생성되었습니다`를 표시하고 `수정 내용으로 다시 생성`을 제공한다.
- 재생성 요청이 실패하면 기존 지도안과 생성 원본을 보존한다. 성공한 경우에만 결과, 생성 원본, 입력 스냅샷을 한 번에 교체한다.

### 날짜와 교시

- 수업 일시는 HTML `date` 입력으로 받아 `YYYY-MM-DD`만 저장한다.
- 교시는 별도 선택 입력으로 받고 값이 있으면 `N교시`로 표시한다. 기본값으로 현재 시각을 넣지 않는다.
- 기존 임시 저장 데이터의 `YYYY-MM-DDTHH:mm` 값은 날짜 부분만 안전하게 이관한다. 시간으로 교시를 추측하지 않는다.
- 화면과 문서에는 날짜와 교시를 사람이 읽는 형식으로 조합하며 ISO 구분자인 `T`를 노출하지 않는다.
- 개요 표의 일시, 장소, 대상 학급, 수업자, 학교급, 학년, 과목, 차시, 단원명, 수업 제목, 수업 모형 값까지 가운데 정렬한다. 성취기준·핵심 질문처럼 긴 내용이 시작되는 행부터는 읽기 편하도록 기존 왼쪽 정렬을 유지한다.

### 공식 과목과 직접 입력 과목

수업 정보 단계에 `목록에서 선택`과 `직접 입력`을 둔다.

- 목록 선택은 현재 동작처럼 학교급에 맞는 공식 과목 목록을 사용한다.
- 직접 입력은 교사가 적은 명칭을 `displaySubject`로 보존해 지도안 제목과 과목 칸에 사용한다.
- AI 과목 매핑은 같은 학교급에 존재하는 공식 과목명만 후보로 받고 관련 과목 1~3개, 신뢰도, 이유를 반환한다.
- 교사는 매핑된 공식 과목을 확인·조정한 뒤 성취기준 단계로 이동한다.
- 성취기준 로컬 검색과 AI 순위화는 확인된 공식 과목들의 합집합 안에서만 수행한다.
- 서버는 AI가 반환한 과목과 성취기준을 교육과정 카탈로그 허용 목록과 대조한다. 목록 밖 과목이나 코드는 버린다.
- AI 매핑이 실패해도 공식 과목을 직접 고르고 로컬 성취기준 검색을 계속 사용할 수 있다.

## 생성 입력 스냅샷

`generatedFrom`은 마지막으로 성공한 생성 요청의 정규화된 입력을 보존한다.

- 수업 기본 정보: 학교급, 학년, 표시 과목, 공식 매핑 과목, 단일·연속 차시, 차시 수, 수업 의도, 학생 지원 필요
- 행정 정보: 날짜, 교시, 장소, 대상 학급, 수업자
- 선택 성취기준: 코드와 원문
- 수업 모형: ID, 이름, 필수 단계와 적용 가이드 버전

비교는 객체 참조가 아니라 정규화된 값으로 수행한다. 화면 오류 문구처럼 생성 결과에 영향을 주지 않는 임시 UI 상태는 비교에서 제외한다. 스냅샷은 임시 저장에 포함하고, 과거 초안에 없으면 현재 입력을 마지막 생성 입력으로 간주해 불필요한 경고를 만들지 않는다.

## 수업 모형 가이드와 생성 검증

### 로컬 가이드

현재 제공하는 모든 수업 모형에 대해 Markdown 가이드를 작성한다. 각 문서는 다음 구조를 사용한다.

- 적용 목적과 적합한 수업 상황
- 반드시 드러나야 하는 단계
- 단계별 교사 행동
- 단계별 학생 행동과 관찰 가능한 산출물
- 주요 발문 예시의 성격
- 피해야 할 잘못된 적용
- 참고 출처와 확인 일자

근거는 교육기관, 대학 교수학습센터, 학술 저장소 등 확인 가능한 자료를 우선한다. 한 연구에서 탐구학습을 문제 인식, 가설 설정, 탐구 절차·자료 수집, 자료 해석·가설 검증, 결론·일반화로 구분한 것처럼, 단순 모형 이름이 아니라 실제 행동 단서를 추출한다.

### 프롬프트

- 선택 모형의 전체 가이드 요약을 생성 요청에 포함한다.
- 문서의 큰 단계명은 학교 현장 표준인 도입·전개·정리를 유지한다.
- 각 단계의 `learningElement`, 교사 활동, 학생 활동, 발문, 예상 반응에 모형별 필수 절차가 순서대로 드러나도록 요구한다.
- 모형 이름만 결과에 복사하고 일반적인 강의안을 만드는 것을 금지한다.
- 수업 의도, 성취기준, 차시 수, 단계 시간 합, 수업 모형 증거를 한 번에 검증한다.

### 검증과 보정

- 공통 검증: 학교급·학년·표시 과목·행정 정보·성취기준·차시 수·시간 합·모형 ID와 이름의 일치
- 모형 검증: 필수 단계가 학습 요소와 활동에 순서대로 대응하고, 교사·학생 행동 중 최소 하나 이상의 관찰 가능한 증거가 존재
- 첫 응답이 부족하면 누락된 모형 단계와 필드를 명시해 한 번 보정 요청
- 두 번째 응답도 실패하면 불완전한 지도안으로 기존 결과를 덮지 않고 재시도를 안내

모형별 자동 테스트는 전체 모형을 대상으로 한다. 실제 Upstage 호출은 비용과 시간을 통제하기 위해 대표적인 구조의 모형을 표본 점검하고, 나머지는 동일한 계약과 보정 경로를 검증한다.

## HWPX 수정 설계

### 진단 원칙

먼저 현재 생성 파일의 `section0.xml`, 표·행·셀 크기 속성, 병합 정보, 문단 높이와 셀 여백을 실제 긴 내용 fixture와 함께 비교한다. PDF가 정상인 점을 근거로 공통 문서 모델을 유지하고 HWPX 렌더러의 레이아웃 계산을 수정한다.

### 렌더링 원칙

- 표 셀의 내용 줄 수, 글자 크기, 줄 간격, 문단 수, 셀 안쪽 여백으로 최소 행 높이를 계산한다.
- 본문 행에 내용을 자르는 고정 높이를 강제하지 않는다.
- 긴 셀은 세로 위쪽 정렬하고 문단 사이 간격을 작게 유지한다.
- 도입·전개·정리 단계 셀은 해당 단계에 속한 행 수만큼 정확히 병합한다.
- 과정 표의 열 너비 합은 A4 본문 폭을 유지하되, 셀 내용이 일부만 표시되지 않도록 행 높이만 확장한다.
- 페이지 경계를 넘는 긴 표는 HWPX가 자연스럽게 다음 페이지로 이어지도록 행 나눔 속성을 점검한다.
- Paperlogy 지정은 유지하되 설치되지 않은 환경에서도 대체 글꼴로 줄바꿈과 행 높이가 무너지지 않을 여유를 둔다.

### HWPX 검증

- 짧은 한 차시, 긴 한 차시, 연속 차시 fixture를 생성한다.
- ZIP 필수 항목, XML well-formedness, 고유 ID, 표 너비 합, 병합 좌표, 행·셀 개수, 필수 텍스트 전체 포함을 검사한다.
- 도입·전개·정리별 모든 교사 활동, 학생 활동, 발문, 반응, 지원, 자료 문장이 잘리지 않고 XML에 존재하는지 확인한다.
- 지원되는 HWPX 검사기로 패키지 유효성을 확인하고, 가능한 로컬 문서 뷰어에서 시각 확인한다. 특정 한컴오피스 버전의 자동화가 불가능하면 그 한계를 변경 기록에 명시한다.

## 교육과정 폴더 이름 변경

- 입력 원본 경로를 `2022_Revised_National_Curriculum/`로 통일한다.
- 빌드 스크립트, 문서, 테스트, 인덱스 참조에서 이전 `복사본` 경로를 제거한다.
- Git에서는 사용자가 수행한 기존 폴더 삭제와 새 폴더 추가를 내용 보존 이름 변경으로 반영한다.
- `.DS_Store`는 추적하지 않는다.
- 카탈로그 재생성 뒤 성취기준 개수와 학교급·학년군·과목 필터 계약을 다시 검증한다.

## 변경 기록

변경 기록은 `docs/change-log/YYYY/MM/YYYY-MM-DD.md`에 저장한다. 각 항목은 `HH:mm KST` 시각과 다음 종류 중 하나를 가진다.

- 화면·사용성
- 생성·AI
- 교육과정·데이터
- 문서 내보내기
- 버그 수정
- 테스트·검증

첫 기록에는 이번 요청 8개를 원문 의미가 유지되도록 요약하고, 각 항목의 상태, 수정 파일, 검증 방법, 남은 제약을 적는다. 이후 요청도 같은 날짜 파일에 시간순으로 추가하고, 날짜가 바뀌면 새 파일을 만든다.

## 오류 처리

- 과목 매핑 실패: 오류와 재시도 버튼을 표시하고 공식 과목 수동 선택을 제공한다.
- 성취기준 추천 실패: 로컬 검색 결과와 기존 선택을 보존한다.
- 생성 실패: 현재 지도안, 편집 내용, 마지막 생성 입력 스냅샷을 보존한다.
- 이전 단계 변경: 생성물을 자동 삭제하지 않고 오래된 결과 상태를 명시한다.
- HWPX 생성 실패: 빈 파일이나 부분 파일을 내려주지 않고 사용자에게 형식별 오류를 표시한다.
- 임시 저장 이관 실패: 전체 앱을 중단하지 않고 안전한 기본값으로 복구한다.

## 테스트와 완료 기준

### 단위·통합 테스트

- 날짜 이관과 표시에서 `T` 및 임의 현재 시각이 나오지 않는다.
- 교시가 화면, 생성 입력, 스키마, 공통 문서 모델, HWPX·DOCX·PDF에 동일하게 전달된다.
- 직접 과목 매핑은 같은 학교급 공식 과목만 허용한다.
- 복수 공식 과목의 성취기준 검색 결과는 학교급·학년군·확인 과목 범위를 벗어나지 않는다.
- 입력 스냅샷 비교는 의미 있는 변경만 감지한다.
- 재생성 실패는 기존 지도안을 보존하고 성공은 결과와 원본을 함께 교체한다.
- 모든 수업 모형의 가이드가 필수 필드를 가지며 프롬프트와 검증기가 같은 단계 계약을 사용한다.
- HWPX 긴 내용 fixture에서 표 내용, 병합, 행 높이, 패키지 구조 계약을 만족한다.

### 브라우저 E2E

- 공식 과목 선택과 직접 과목 입력 두 흐름을 완주한다.
- 생성 후 요약 카드와 이전 선택을 확인한다.
- 완료 단계를 눌러 입력을 수정하고 변경 경고를 확인한 뒤 재생성한다.
- 재생성 실패 후 기존 편집값이 남고, 재시도 성공 후 새 지도안으로 바뀐다.
- 데스크톱과 모바일에서 표가 가로로 깨지지 않고 단계 이동이 가능하다.
- HWPX, DOCX, PDF를 다시 내려받을 수 있다.
