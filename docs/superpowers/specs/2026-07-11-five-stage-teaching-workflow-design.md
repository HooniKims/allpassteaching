# 5단계 교수·학습·평가·기록 워크플로우 설계

## 목표

교사가 하나의 수업 프로젝트 안에서 지도안, 학습지, 수행평가와 루브릭, 학생 제출물 OCR·채점, 과목별 세부능력 및 특기사항까지 순서대로 만들고 편집·승인할 수 있는 MVP를 구현한다. 모든 AI 결과는 초안이며 교사가 최종 검토하고 승인한다.

## 1. 범위와 기본 원칙

- 학교급은 일반 초등학교, 중학교, 일반고등학교만 지원한다.
- 상단의 5개 프로세스 탭은 항상 선택할 수 있다. 선행 결과가 없으면 해당 탭 안에서 필요한 이전 단계와 이동 버튼을 안내한다.
- 각 단계는 이전 결과의 생성 스냅샷을 보관한다. 지도안이나 루브릭이 바뀌어도 기존 결과를 즉시 삭제하지 않고 `이전 내용으로 생성됨` 상태를 표시한 뒤 교사가 다시 생성한다.
- 브라우저의 로컬 저장소에 프로젝트 JSON만 보관한다. 업로드한 PDF 원본은 보관하지 않는다.
- 학생 이름, OCR 원문, 점수, 세특 초안은 민감한 교육 정보로 취급한다. API 처리 목적과 저장 범위를 화면에 알리고 `학생 자료 모두 지우기`를 제공한다.
- 자동 채점과 세특은 확정값이 아니다. 교사가 OCR 원문과 루브릭 근거를 확인하고 학생별 `승인`을 눌러야 다음 단계의 확정 자료로 사용한다.

## 2. 상단 5단계 구조

1. `지도안`: 기존 4단계 지도안 작성 화면 전체를 포함한다.
2. `학습지`: 확정 또는 편집 중인 지도안을 바탕으로 수업 모형에 맞는 학습지 형식을 추천하고 학습지와 교사용 예시 답안을 생성한다.
3. `수행평가`: 지도안의 성취기준·학습 목표·활동을 바탕으로 수행과제와 4수준 분석적 루브릭을 생성한다.
4. `OCR·채점`: 학생 PDF 여러 개를 일괄 선택하고 파일별 학생 이름을 확인한 뒤 OCR, 루브릭 채점, 교사 승인을 수행한다.
5. `세특`: 승인된 학생별 수행 증거를 바탕으로 과목별 세부능력 및 특기사항 초안을 생성하고 교사가 편집·복사한다.

탭에는 `완료`, `검토 필요`, `선행 단계 필요` 상태를 표시한다. 모바일에서는 가로 스크롤 가능한 탭으로 유지하되 현재 단계와 상태를 텍스트로 함께 제공한다.

## 3. 학교급·학년별 과목 체계

과목 선택 목록의 마지막 항목은 모든 학교급에서 `직접 입력`이다. 별도의 `과목 입력 방식` 라디오 그룹은 제거한다. `직접 입력`을 선택한 경우에만 직접 입력 필드와 공식 과목 연결 패널을 표시한다.

### 초등학교

- 1–2학년: 국어, 수학, 바른 생활, 슬기로운 생활, 즐거운 생활
- 3–4학년: 국어, 수학, 사회, 과학, 도덕, 체육, 음악, 미술, 영어
- 5–6학년: 3–4학년 과목과 실과

### 중학교

- 공통 교과: 국어, 수학, 사회, 역사, 과학, 도덕, 기술·가정, 정보, 체육, 음악, 미술, 영어
- 선택과목: 한문, 환경, 보건, 진로와 직업

### 일반고등학교

과목 목록은 `국어`, `수학`, `영어`, `사회·역사`, `과학`, `체육·예술`, `기술·가정·정보·한문`, `교양` optgroup으로 나눈다. 공통과목과 현장에서 자주 선택하는 일반 선택과목을 우선 제공하고 목록에 없는 과목은 직접 입력한다.

- 국어: 공통국어1, 공통국어2, 화법과 언어, 독서와 작문, 문학
- 수학: 공통수학1, 공통수학2, 기본수학1, 기본수학2, 대수, 미적분Ⅰ, 확률과 통계, 미적분Ⅱ, 기하
- 영어: 공통영어1, 공통영어2, 기본영어1, 기본영어2, 영어Ⅰ, 영어Ⅱ, 영어 독해와 작문
- 사회·역사: 한국사1, 한국사2, 통합사회1, 통합사회2, 세계시민과 지리, 세계사, 사회와 문화, 정치, 법과 사회, 경제
- 과학: 통합과학1, 통합과학2, 과학탐구실험1, 과학탐구실험2, 물리학, 화학, 생명과학, 지구과학
- 체육·예술: 체육1, 체육2, 운동과 건강, 음악, 음악 연주와 창작, 미술, 미술 창작
- 기술·가정·정보·한문: 기술·가정, 정보, 인공지능 기초, 데이터 과학, 한문, 한문 고전 읽기
- 교양: 진로와 직업, 생태와 환경, 인간과 철학, 논리와 사고, 인간과 심리, 교육의 이해, 삶과 종교, 보건, 인간과 경제활동, 논술

구체적인 표시 과목은 기존 카탈로그의 넓은 과목군 별칭과 연결한다. 검색 질의에는 표시 과목명을 함께 포함해 같은 과목군 안에서도 관련 성취기준이 먼저 추천되도록 한다.

## 4. 프로젝트 데이터와 의존성

새 저장 키 `allpass.teaching-workflow`는 다음 데이터를 보관한다.

```text
TeachingProject
├─ activeProcess
├─ lessonSnapshot
├─ worksheet { sourceHash, format, document, teacherKey }
├─ assessment { sourceHash, task, rubric, totalPoints }
├─ submissions[]
│  ├─ id, studentName, fileName, status
│  ├─ extractedText, ocrModel, pageCount
│  ├─ grading { criterionScores, totalScore, evidence, feedback }
│  └─ approved
└─ records[] { submissionId, sourceHash, text, approved }
```

기존 `allpass.lesson-plan` 저장 키는 유지해 기존 초안과 테스트를 깨뜨리지 않는다. 최상위 워크플로우가 지도안 초안의 최신 스냅샷을 받아 후속 단계 의존성을 계산한다. PDF `File` 객체와 원본 바이트는 로컬 저장소에 넣지 않는다.

## 5. 학습지 생성

수업 모형 자료와 함께 다음 형식 레지스트리를 제공한다.

- 직접 교수: 설명 확인·안내된 연습·독립 연습지
- 개념 학습: 정례/비례 비교표와 개념 적용지
- 탐구·실험: 문제·가설·변인·관찰 기록·결론 학습지
- 문제 해결: 문제 이해·계획·실행·반성 기록지
- 프로젝트: 역할·일정·산출물 기준·중간 점검표
- 협동 학습: 역할 분담·개인 책무·상호 평가표
- 토의·토론: 쟁점·주장·근거·반론·합의 기록지
- 역할놀이·디자인·블렌디드·교과 특화: 해당 모형 단계에 맞춘 전용 기록지

AI는 지도안과 형식 가이드를 받아 최적 형식과 선정 이유를 반환한다. 교사는 다른 형식을 선택해 다시 생성할 수 있다. 학습지는 제목, 안내, 학생 정보란, 섹션, 질문, 응답 공간으로 구성하고 교사용 예시 답안은 별도 표시한다. 모든 필드는 웹에서 편집하며 PDF로 저장한다.

## 6. 수행평가와 루브릭

수행평가에는 과제명, 성취기준, 상황·역할·대상·산출물, 수행 절차, 제출 조건, 준비물, 유의점이 포함된다. 기본 루브릭은 4수준 분석적 루브릭이며 각 평가 요소마다 배점, 수준별 기술, 관찰 증거를 가진다. 배점 합은 기본 100점이고 교사가 수정할 수 있다. 생성·편집 결과는 PDF로 저장한다.

루브릭은 성취기준 원문과 지도안 활동에서 직접 근거를 가져오며 태도만으로 점수를 결정하거나 OCR에 없는 내용을 추정하지 않도록 프롬프트에서 금지한다.

## 7. PDF OCR·학생별 채점

- 파일 입력은 `multiple` PDF만 허용하고 한 번에 최대 10개, 파일당 최대 10MB로 제한한다.
- 파일명에서 확장자를 제거한 값을 학생 이름 기본값으로 사용하며 교사가 수정한다.
- 브라우저는 파일을 최대 2개씩 처리해 API 과부하를 막고 학생별 진행·성공·실패 상태를 표시한다.
- 서버는 `multipart/form-data`로 받은 파일을 Upstage `POST /v1/document-digitization`에 전달한다.
- 공식 예제에 맞춰 `model=document-parse`, `ocr=force`를 사용한다. 응답의 `content.html` 또는 텍스트 요소를 안전한 일반 텍스트로 정규화한다.
- OCR 원문은 교사가 직접 수정할 수 있다. 비어 있거나 지나치게 짧으면 채점 버튼을 비활성화하고 재처리를 안내한다.
- 채점 API는 승인된 루브릭, 학생 OCR 원문, 지도안 성취기준만 사용해 요소별 점수·직접 근거·피드백을 JSON으로 반환한다. 총점은 서버에서 요소별 점수를 합산해 계산한다.
- 학생별 점수와 근거는 교사가 수정할 수 있고 승인 전에는 세특 생성 대상이 아니다.

실제 OCR 검증은 코드에 포함된 한국어 PDF fixture를 사용해 API 연결, 비어 있지 않은 추출, 핵심 문구 포함을 확인한다. 실제 필기체 학생 자료가 제공되지 않았으므로 필기체 정확도 수치는 주장하지 않는다.

## 8. 세특 생성

세특 입력은 학생 이름, 학교급·학년·과목, 성취기준, 수행과제, 승인된 루브릭 점수와 직접 관찰 근거다. 프롬프트는 점수 나열 대신 학습 과정·수행 특성·성장·교과 역량을 근거 중심으로 서술하고 OCR에 없는 사실, 인성 단정, 다른 학생과의 비교를 금지한다.

기본 길이는 500자 이내이며 교사가 300–1000자 범위에서 조절한다. 학생별 생성, 전체 미생성 학생 일괄 생성, 편집, 글자 수 표시, 복사를 제공한다.

## 9. 오류·보안·접근성

- 한 학생의 OCR·채점 실패가 다른 학생 처리를 중단하지 않는다.
- API 오류는 학생별 재시도 버튼과 상태 코드에 맞는 한국어 메시지를 제공한다.
- 파일 MIME, 확장자, 크기, 개수를 클라이언트와 서버 양쪽에서 검사한다.
- API 키, PDF 바이트, Upstage 원문 응답 전체는 로그에 남기지 않는다.
- 탭은 `role=tablist`, 각 화면은 `tabpanel`을 사용하고 키보드 화살표 이동과 포커스 표시를 제공한다.
- 생성 중 버튼 상태, 진행률, 오류는 스크린리더가 인지할 수 있는 live region으로 알린다.

## 10. 검증 기준

- 학교급·학년별 과목 목록, 별칭, 직접 입력 전환을 단위·컴포넌트 테스트로 검증한다.
- 각 생성 API는 Zod 경계, Upstage 오류, 한 차례 보정, 입력 보존을 테스트한다.
- PDF 업로드는 파일 수·크기·MIME, multipart 전달, OCR 정규화, 학생별 부분 실패를 테스트한다.
- 데스크톱·모바일 E2E는 지도안 생성부터 학습지·루브릭·2명 PDF OCR·채점 승인·세특 생성까지 한 흐름으로 완주한다.
- 실제 Upstage OCR smoke test는 별도 스크립트로 실행하고 키·원문 전체를 출력하지 않는다.
- 전체 Vitest, Playwright, Next.js 빌드, PDF 렌더링과 페이지 수를 최종 검증한다.

## 11. MVP 제약

- 로그인, 서버 데이터베이스, 학급 명렬표, 학교 시스템 연동은 포함하지 않는다.
- 원본 PDF 재열람은 지원하지 않는다. 새로고침 후에는 추출 텍스트와 채점 결과만 남는다.
- 실제 필기체 품질 평가는 사용자가 비식별화된 표본을 제공한 후 별도 벤치마크로 수행한다.
- HWPX 학습지·수행평가 출력은 이번 범위에서 제외하고 PDF를 우선 지원한다.
