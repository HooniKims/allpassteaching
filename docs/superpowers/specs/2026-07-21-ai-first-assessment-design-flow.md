# AI 우선 수행평가 설계·수행평가지 분리 흐름

## 목표

교사가 수행평가 생성 전에 많은 설정을 입력하지 않도록 한다. AI가 지도안과 교사가 확정한 성취기준에서 수행과제·평가영역·루브릭 초안을 먼저 만들고, 교사가 수정한 최종 설계를 기준으로 학생용 수행평가지와 교사용 채점 참고를 별도로 생성한다. 성취기준은 AI 추천뿐 아니라 현재 학교급·학년군·교과 범위의 공식 목록에서 교사가 직접 선택할 수 있어야 한다.

## 성취기준 추천·직접 선택 흐름

1. 성취기준 단계 상단에 현재 범위를 `중학교 1~3학년군 · 사회 · 지리/일반사회`처럼 명시한다.
2. AI는 이 범위 안의 공식 성취기준 중 지도안 주제와 관련성이 높은 3~5개를 추천한다. 추천 결과는 후보일 뿐 자동 선택하지 않는다.
3. AI 추천과 별개로 모든 과목에 `교육과정에서 직접 선택` 영역을 항상 표시한다. 교사는 성취기준 코드·내용 검색으로 현재 학교급·학년군·과목 범위의 전체 목록을 탐색하며, 사회·역사처럼 원천 교과를 공유하는 과목은 영역 필터도 사용할 수 있다.
4. AI 추천과 직접 선택은 하나의 선택 목록을 공유한다. 선택 출처와 무관하게 같은 성취기준은 중복되지 않으며, 교사는 최대 10개까지 추가·삭제할 수 있다.
5. AI 추천이 실패하거나 결과가 없어도 직접 선택은 계속 사용할 수 있다.
6. 교사가 확정한 성취기준만 지도안과 1차 수행평가 설계 생성의 입력으로 사용한다.

## 교육과정 카탈로그와 범위 모델

- 교육과정 추출기는 괄호가 포함된 공식 코드도 인식해야 한다. 예를 들어 `[9사(지리)01-01]`, `[9사(일사)08-01]`을 누락 없이 추출하고 이어지는 설명 문단을 해당 성취기준에 결합한다.
- 카탈로그 항목에는 기존 학교급·학년군·교과 정보와 함께 교과 내 영역인 `subjectArea`를 둔다. 중학교 사회의 `9사(지리)`는 `지리`, `9사(일사)`는 `일반사회`, `9역`은 `역사`로 정규화한다.
- 중학교에서 교사가 `사회`를 선택하면 검색 범위를 `교과: 사회`, `영역: 지리·일반사회`로 제한한다. `역사`를 선택하면 같은 원천 교과 안에서도 `영역: 역사`만 허용한다. 다른 교과는 기존 학교급·학년군·교과 범위를 유지한다.
- 로컬 직접 검색과 추천 API는 동일한 범위 계산 함수를 사용한다. 추천 API는 범위 밖의 항목을 AI에 전달하지 않으며, AI가 반환한 코드도 서버에서 다시 범위 검증한다.
- 직접 선택 목록은 범위 안의 전체 카탈로그를 대상으로 한다. 기존 추천 후보 수 제한은 AI 재정렬에만 적용하고 직접 선택 결과를 자르지 않는다.
- 기존 저장 데이터와 지도안 계약은 유지한다. `subjectArea`는 검색·표시 메타데이터로 추가하고, 선택된 성취기준의 기존 코드·내용·교과 필드는 그대로 보존한다.

## 사용자 흐름

1. 수행평가 단계의 초기 화면은 현재 지도안 제목과 성취기준, `AI로 수행평가 초안 만들기` 버튼을 보여준다.
2. AI는 평가 이름, 도착점, 성공 증거, 산출물, 수행 과정, 총점, 성취수준, 과정 비중, 평가영역과 수준별 루브릭을 자동 제안한다.
3. 교사는 생성된 수행과제와 루브릭의 문구·배점·수준 기준을 직접 수정한다. 총점·수준 수·과정 비중·산출물 유형 같은 생성 옵션은 `세부 설정`에서 수정한다.
4. 유효한 설계에는 `이 설계로 수행평가지 만들기`를 주 행동으로 제공한다.
5. AI는 교사가 수정한 설계만을 기준으로 학생용 문항, 응답 공간, 학생 안내문과 교사용 채점 참고를 생성한다.
6. 교사는 수행평가지를 검토·수정한 뒤 PDF 또는 HWPX로 저장한다.

## 생성 경계와 데이터 구조

- 1차 생성은 `assessmentDesign`을 반환한다. 이 구조는 `backwardDesign`, `task`, `rubric`, `scoring`, 생성 설정과 표지 사용 여부를 포함하고 `studentSheet`와 실제 표지 내용은 포함하지 않는다.
- 2차 생성은 검증된 `assessmentDesign`과 현재 지도안을 입력받아 `studentSheet`와 `cover`를 반환한다. 서버는 둘을 합쳐 기존 내보내기·채점 흐름이 사용하는 완성된 `assessment`를 만든다.
- 설계 스키마와 완성본 스키마를 분리한다. 두 스키마가 공유하는 수행과제·루브릭 계약은 하나의 공통 스키마로 정의해 배점, 성취기준 연결과 수준 설명 검증이 달라지지 않게 한다.
- 저장소는 `assessmentDesign`, `assessment`, 각 결과의 출처 해시를 별도로 보존한다. 기존 저장 데이터는 완성된 `assessment`에서 설계 부분을 추출해 마이그레이션한다.

## 화면 상태

### 성취기준 선택

- `범위 확인`: 현재 학교급·학년군·교과와 교과 내 영역을 보여준다.
- `추천 전/추천 중/추천 완료`: 추천 상태와 무관하게 공식 목록 직접 선택 영역을 유지한다.
- `직접 선택`: 검색어와 영역 필터로 공식 목록을 좁히며, 결과마다 코드·내용·영역과 선택 상태를 표시한다.
- `선택 완료`: AI 추천과 직접 선택에서 추가한 항목을 한 목록에 보여주고 선택 개수와 최대 10개 제한을 안내한다.

### 수행평가 설계

- `초안 없음`: 지도안 요약과 AI 초안 생성 행동만 표시한다.
- `설계 편집 중`: 수행과제·루브릭 편집기와 접힌 세부 설정, 수행평가지 생성 행동을 표시한다.
- `수행평가지 생성 중`: 설계 편집본을 유지하고 생성 진행 상태를 표시한다.
- `완성본 검토`: 설계 편집기와 수행평가지 편집기, 내보내기 행동을 표시한다.
- 수행평가지 생성 후 설계가 바뀌면 완성본을 삭제하지 않고 `설계 변경됨`으로 표시한다. 내보내기와 확인 완료는 막고, 현재 편집본을 기준으로 다시 생성하도록 한다.
- 다시 생성된 설계나 수행평가지는 기존 편집본을 즉시 덮어쓰지 않고 후보로 보여준 뒤 교사가 적용한다.

## 기본값과 교사 소유권

- 첫 초안의 총점, 성취수준 수, 과정 점수 비중과 산출물 유형은 AI가 지도안에서 제안한다. AI가 안정적으로 판단하기 어려우면 20점, 4수준, 과정 20%, 서술형 탐구 산출물을 기본값으로 사용한다.
- 교사가 수정한 값은 이후 AI 호출의 입력 계약이 되며 AI가 임의로 되돌릴 수 없다.
- 수행평가지 생성은 교사가 수정한 평가영역 id, 배점, 수준 순서와 수준 점수를 그대로 보존한다.
- 자동 생성 내용은 항상 `AI 초안`으로 표시하고, 최종 확인 책임이 교사에게 있음을 짧게 안내한다.

## 오류 처리

- 교육과정 원천 데이터에 현재 범위의 항목이 없으면 일반적인 검색 결과 없음과 구분해 카탈로그 점검이 필요한 상태로 안내한다.
- AI 추천 실패는 직접 선택을 막지 않는다. 기존 선택 항목과 검색·필터 상태도 유지한다.
- 추천 응답에 범위 밖 코드가 포함되면 적용하지 않고 서버 로그에 검증 실패를 남긴다.
- 1차 AI 생성이 실패하면 지도안에서 만든 구체적인 안전 초안을 제공하되, 플레이스홀더나 동일한 수준 설명은 허용하지 않는다.
- 2차 생성이 실패해도 교사가 수정한 설계와 이전 수행평가지는 그대로 유지한다.
- 생성 도중 입력이 변경되면 응답을 자동 적용하지 않고 후보로 보관한다.
- 성취기준 연결, 배점 합계, 과정 비중 또는 루브릭 수준 계약이 유효하지 않으면 해당 위치의 수정 안내와 함께 수행평가지 생성 행동을 비활성화한다.

## 접근성 및 반응형

- 성취기준 검색·영역 필터에는 연결된 레이블을 제공하고, 선택 상태와 선택 개수 변화는 보조기기에 전달한다.
- 모바일에서는 추천과 공식 목록을 위아래로 배치하고, 데스크톱에서는 두 영역을 구분하되 선택 목록은 공통으로 유지한다.
- 초기 화면과 각 생성 단계의 주 행동은 하나만 강조하며 키보드로 접근 가능해야 한다.
- `세부 설정`은 실제 disclosure control을 사용하고 펼침 상태를 보조기기에 전달한다.
- 생성 상태는 `status`, 오류는 `alert`로 알리고 기존 편집 영역의 포커스를 빼앗지 않는다.
- 모바일에서는 평가영역별 카드 안에서 수준 기준을 세로로 읽게 하고, 데스크톱에서는 기존 루브릭 그리드를 유지한다.

## 검증

- 추출기 단위 테스트로 괄호가 있는 사회 성취기준 코드와 여러 줄 설명이 카탈로그에 포함되는지 검증한다.
- 카탈로그 생성 테스트로 중학교 사회에 `지리`·`일반사회` 항목이 존재하고 역사 항목과 영역 메타데이터가 분리되는지 검증한다.
- 검색 단위 테스트로 `사회` 범위에는 `9사(지리)`·`9사(일사)`만, `역사` 범위에는 `9역`만 반환되는지 검증한다.
- 추천 API 테스트로 AI에 전달되는 후보와 최종 응답이 동일한 엄격 범위를 지키는지 검증한다.
- 성취기준 컴포넌트 테스트로 AI 추천과 공식 목록이 함께 표시되고, 검색·영역 필터·공통 선택 목록·최대 10개 제한·추천 실패 후 직접 선택을 검증한다.
- 선택한 성취기준이 지도안 저장과 1차 수행평가 설계 입력까지 그대로 전달되는지 통합 테스트로 검증한다.
- 설계 스키마 단위 테스트로 학생용 문서 없이 수행과제·루브릭 계약이 유효한지 검증한다.
- 1차 생성 API 테스트로 수동 입력 없이 지도안만으로 초안을 만들고, 안전 초안도 구체적인 수준 설명을 제공하는지 검증한다.
- 2차 생성 API 테스트로 교사가 수정한 영역 id·배점·수준 점수를 보존하며 문항과 채점 참고를 생성하는지 검증한다.
- 저장소 마이그레이션 테스트로 기존 완성본을 설계와 완성본 상태로 안전하게 불러오는지 검증한다.
- 컴포넌트 테스트로 초기 한 버튼 흐름, 접힌 세부 설정, 편집 후 수행평가지 생성, 설계 변경 시 stale 상태와 후보 적용을 검증한다.
- Playwright 데스크톱·모바일에서 `성취기준 직접 선택 → AI 초안 생성 → 교사 수정 → 수행평가지 생성 → 저장` 전체 흐름을 실제로 수행한다.

## 범위 제외

- 자동 승인이나 자동 점수 확정은 하지 않는다.
- 수행평가지 생성 전에 별도의 다단계 마법사나 추가 필수 질문을 만들지 않는다.
- 직접 선택은 모든 과목에 제공한다. 다만 사회·역사 외 교과에 근거 없는 교과 내 영역 분류를 새로 만들지 않으며, 기존 통합 수업 교과 선택기는 유지한다.
- 이번 변경에서 채점·OCR·학교생활기록부 생성 흐름은 바꾸지 않는다.
