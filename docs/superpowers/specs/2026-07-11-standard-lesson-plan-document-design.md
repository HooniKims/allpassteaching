# 표준 교수·학습 과정안 문서 설계

## 목표

현재의 텍스트 나열형 내보내기를 학교 현장에서 결재, 공유, 공개수업 및 장학 자료로 사용할 수 있는 정식 교수·학습 과정안으로 바꾼다. HWPX, DOCX, PDF는 하나의 공통 문서 모델을 사용하며 항목, 표 구조, 내용 순서가 일치해야 한다.

## 기본 형식

- 기본 서식은 `A안 · 학교 현장 표준형`이다.
- 한 차시는 기본 2쪽 분량의 정식형으로 구성한다.
- 연속 차시는 차시마다 새 페이지에서 시작한다.
- 일시, 장소, 대상 학급, 수업자는 선택 입력이며, 값이 없으면 문서에 작성 가능한 빈칸으로 출력한다.
- Paperlogy를 기본 글꼴로 사용하되, HWPX 환경에서 해당 글꼴이 없을 때에도 문서 구조와 가독성이 유지되어야 한다.

## 차시별 문서 구조

### 1쪽: 수업 개요와 교수·학습 과정

문서 제목은 `교수·학습 과정안`으로 한다. 상단 개요 표에는 다음 항목을 둔다.

- 일시
- 장소
- 대상 학급
- 수업자
- 학교급과 학년
- 과목
- 단원 또는 수업 주제
- 차시와 전체 차시 수
- 수업 모형
- 성취기준 코드와 원문
- 학습 목표
- 핵심 질문
- 준비물

교수·학습 과정 표는 다음 6열을 사용한다.

| 단계 | 학습 요소 | 교사 활동 | 학생 활동 | 시간 | 자료·유의점 |
| --- | --- | --- | --- | --- | --- |

단계는 도입, 전개, 정리를 기본으로 하며 각 행에 주요 발문, 예상 학생 반응, 개별화 지원을 실제 수업 흐름에 맞게 포함한다. 단계별 시간 합은 차시 시간과 정확히 같아야 한다.

### 2쪽: 평가, 지원, 성찰과 연결

과정중심평가 표는 다음 4열을 사용한다.

| 평가 요소 | 평가 방법 | 관찰 증거 | 수준별 피드백 |
| --- | --- | --- | --- |

그 아래에 개별화·지원 전략, 수업 후 성찰, 다음 차시 연결 내용을 배치한다. 마지막 차시에는 다음 차시 연결 대신 단원 학습의 후속 활동 또는 정리 방향을 기록한다.

## 입력과 편집 경험

수업 정보 단계에 일시, 장소, 대상 학급, 수업자 선택 입력란을 추가한다. AI 생성 뒤에는 텍스트 카드가 아니라 실제 문서와 같은 표 기반 미리보기를 제공한다. 교사는 다음 내용을 모두 수정할 수 있다.

- 상단 행정 정보
- 수업 제목과 핵심 질문
- 학습 목표와 준비물
- 단계별 학습 요소, 교사 활동, 학생 활동, 시간, 자료·유의점
- 주요 발문과 예상 학생 반응
- 평가 방법, 관찰 증거, 수준별 피드백
- 지원 전략, 성찰, 다음 차시 연결

편집값은 기존 임시 저장 흐름에 포함한다. 기존 초안에 새 필드가 없으면 빈 문자열 또는 합리적인 기본값을 채워 불러온다.

## 생성 데이터 계약

기존 지도안 스키마를 확장해 다음 필드를 구조화한다.

- `metadata`: date, place, className, teacherName
- `unitTitle`
- `essentialQuestion`
- 차시별 `learningElement`
- 단계별 `teacherQuestions`
- 단계별 `expectedStudentResponses`
- 단계별 `supportNotes`
- 평가별 `method`
- 평가별 `levelFeedback`
- 차시별 `nextSessionConnection`

Upstage 프롬프트는 선택한 성취기준 원문과 코드를 그대로 사용해야 한다. 요청한 차시 수, 차시별 시간, 도입·전개·정리 구조를 지켜야 하며 관찰 가능한 목표와 평가 증거가 대응해야 한다. 검증 실패 시 오류 목록을 포함해 한 번 자동 교정한다. 두 번째 검증도 실패하면 불완전한 결과나 파일을 제공하지 않고 재시도를 안내한다.

## 공통 문서 모델

`lessonPlanSchema`의 데이터를 내보내기 전용 공통 모델로 변환한다. 공통 모델은 제목 영역, 개요 표, 차시별 과정 표, 평가 표, 지원·성찰·연결 영역과 명시적 페이지 나눔 정보를 가진다.

HWPX, DOCX, PDF 생성기는 이 모델만 소비한다. 생성기별로 내용을 다시 판단하거나 누락하지 않는다. 이를 통해 세 형식의 항목과 문구가 동일하게 유지된다.

## 파일별 렌더링

### HWPX

- OWPML 표 요소를 사용해 실제 셀, 테두리, 배경, 병합, 여백을 구성한다.
- A4 본문 폭 안에서 6열 너비 합을 정확히 맞춘다.
- 제목, 표 머리글, 본문용 문자·문단 스타일과 테두리 스타일을 header.xml에 정의한다.
- 차시 시작 전 명시적 페이지 나눔을 사용한다.
- mimetype 첫 항목과 무압축 규칙, 네임스페이스, ID 및 itemCnt 정합성을 지킨다.

### DOCX

- Word의 실제 Table, TableRow, TableCell을 사용한다.
- 반복 머리글, 셀 음영, 고정 열 너비와 페이지 나눔을 적용한다.
- 제목과 표 안의 모든 글꼴을 Paperlogy로 지정한다.

### PDF

- Paperlogy TTF를 포함한다.
- 텍스트 좌표 나열 대신 공통 표 레이아웃 엔진으로 셀 높이, 줄바꿈, 테두리, 배경을 계산한다.
- 행이 페이지 하단을 넘어가면 다음 페이지로 안전하게 넘기고 표 머리글을 반복한다.

## 검증

### 구조 검증

- HWPX: 필수 ZIP 항목, XML well-formedness, 스타일 참조, 표 행·열·셀 병합, 열 너비 합, 페이지 나눔을 검사한다.
- DOCX: 문서 XML의 표 개수, 필수 머리글, 차시별 페이지 나눔과 필수 텍스트를 검사한다.
- PDF: PDF 헤더, 포함 글꼴, 페이지 수, 필수 텍스트와 렌더링 범위를 검사한다.

### 내용 검증

- 선택한 성취기준 코드와 원문이 변경되지 않는다.
- 생성 차시 수가 요청과 같다.
- 각 차시 단계 시간 합이 차시 시간과 같다.
- 학습 목표, 수업 활동, 관찰 증거, 피드백이 서로 연결된다.
- 필수 표 항목이 비어 있지 않다. 행정 정보는 예외이며 빈칸 출력을 허용한다.

### 사용자 흐름과 시각 검증

- 행정 정보 입력부터 AI 생성, 표 편집, HWPX·DOCX·PDF 다운로드까지 브라우저 E2E로 검증한다.
- 단일 차시와 연속 차시, 짧고 긴 활동 문장을 모두 시험한다.
- 데스크톱과 모바일 미리보기의 가로 넘침, 겹침, 잘림을 확인한다.
- 샘플 파일을 실제로 생성하고 HWPX 검사기, DOCX 내부 XML 검사, PDF 렌더링 이미지 검토를 통과시킨다.

## 범위 밖

- 교육청 또는 개별 학교가 제공한 특정 서식의 1:1 복제
- 결재란, 학교 로고, 전자서명
- 바이너리 HWP 출력
- 교사가 임의로 열을 추가하거나 표 전체 구조를 설계하는 서식 편집기

특정 학교 서식 복제는 향후 사용자가 HWPX 기준 파일을 제공할 때 별도 기능으로 다룬다.
