# 백워드 설계 기반 수행평가·증거 채점 확장 설계

## 1. 목적과 관계

이 문서는 기존 `2026-07-11-five-stage-teaching-workflow-design.md`를 대체하지 않고, 수행평가·학생 자료·채점·기록 영역을 확장한다. 두 문서가 충돌하면 수행평가, 루브릭, 학생 명단, PDF 업로드·열람, 채점, 세특과 진행 표시는 이 문서를 우선한다. 교사가 성취기준에서 출발해 수용 가능한 성취 증거를 먼저 정하고 수행과정과 수업 지원을 설계하도록 한다. 점수는 학생의 실수를 깎는 장치가 아니라, 학생이 보여준 성취와 성장의 증거를 행정적으로 요약하는 값으로 사용한다.

상단의 다섯 단계인 `지도안`, `학습지`, `수행평가`, `OCR·채점`, `세특`은 유지한다. 모든 AI 결과는 교사가 편집할 수 있는 초안이며 교사의 원본 확인과 승인이 없으면 확정 자료로 사용하지 않는다.

## 2. 확정된 평가 원칙

- 수행평가는 성취기준, 전이 목표, 성취 증거, 수행계획 순으로 설계한다.
- 학생의 성격이나 인성을 `성실함`으로 추정하지 않는다. 계획, 중간 산출물, 피드백 반영, 수정 이력, 자기평가처럼 관찰 가능한 수행과정만 증거로 사용한다.
- 초안의 오류나 초기 미숙함을 자동 감점하지 않는다. 교사가 별도로 정하지 않는 한 최종 또는 가장 최근의 충분한 증거를 우선한다.
- 결과물의 완성도와 수행과정 증거를 구분해 보여주고, 과정 증거를 점수에 포함할지는 평가 설계에서 교사가 선택한다.
- AI는 점수를 확정하지 않고 허용된 루브릭 수준과 근거를 추천한다. 총점은 서버가 검증된 영역 점수를 합산해 계산한다.
- OCR 또는 시각 요소 판독이 불확실하면 점수를 추정하지 않고 `교사 확인 필요`로 보낸다.

## 3. 수행평가 안의 백워드 설계

현재 다섯 단계 순서를 바꾸지 않고 `수행평가` 단계를 세 개의 내부 설계 구역으로 구성한다.

### 3.1 원하는 결과

- 선택한 2022 개정 교육과정 성취기준
- 학생이 새로운 상황에서 수행해야 할 전이 목표
- 오래 남아야 할 핵심 이해
- 탐구와 수행을 이끄는 핵심 질문
- 필요한 지식과 기능

AI는 현재 지도안과 학습지를 참고하되 성취기준 원문을 바꾸지 않는다. 지도안 활동과 원하는 결과가 맞지 않으면 자동으로 덮어쓰지 않고 `설계 정합성 확인`에서 불일치와 수정 제안을 보여준다.

### 3.2 수용 가능한 증거

- GRASPS의 목표, 역할, 대상, 상황, 산출물, 성공 기준으로 실제적 수행과제를 작성한다.
- 각 성취기준을 하나 이상의 평가영역과 연결한다.
- 각 평가영역은 학생 답안에서 확인할 증거 형태를 가진다. 예: 설명, 계산 과정, 표, 그래프, 실험 기록, 그림, 발표 관찰 기록, 수정 전후 비교.
- `성취기준 → 전이 목표 → 평가영역 → 학생 증거 → 점수 근거` 연결표를 생성한다.
- 모든 선택 성취기준은 최소 한 번 연결되어야 하며 연결되지 않은 평가영역은 승인할 수 없다.

### 3.3 수행·지원 계획

- 과제 안내, 수행 단계, 중간 점검, 교사 피드백, 수정, 최종 제출, 자기평가 순서를 생성한다.
- 각 중간 점검에는 제출할 증거와 교사가 제공할 피드백 목적을 적는다.
- 학생이 피드백을 반영할 기회를 최소 한 번 제공한다.
- 결과는 지도안·학습지와 비교해 정합성을 표시하며 교사가 필요한 수정 사항을 확인한다.

## 4. 수행평가 생성 입력

교사는 AI 생성 전에 다음을 입력하거나 선택한다.

- 평가명과 추가 요구사항
- 전체 총점
- 기본 성취수준 개수: 4수준, 허용 범위 2~6수준
- 과정 증거의 점수 반영 여부와 희망 비중
- 원하는 산출물과 답안 유형
- 초안·중간 점검·수정본·최종본 사용 여부
- 수식, 표, 그래프, 도표, 그림 등 시각 답안 예상 여부
- 학생당 안내 표지 포함 여부

AI는 성취기준과 입력을 바탕으로 백워드 설계, 수행과제, 루브릭, 학생용 안내 표지를 함께 생성한다. 교사는 전체 또는 선택한 영역만 다시 생성할 수 있으며, 재생성은 기존 편집 내용을 즉시 지우지 않고 비교 후 적용한다.

## 5. 클리포 호환형 가변 루브릭

### 5.1 점수 구조

- 교사가 `전체 총점`을 먼저 입력한다. 기본값은 100점이지만 고정값이 아니며 1~1,000 사이의 정수를 허용한다.
- AI가 평가영역별 총점과 영역별 급간 점수를 생성한다.
- A안의 고정 차감 계산을 사용한다. 예: 영역 총점 20점, 급간 5점, 4수준이면 `20, 15, 10, 5점`이다.
- 계산은 수준별 허용 점수를 만드는 규칙이며 화면에서는 감점이 아니라 `획득한 성취 증거 점수`로 설명한다.
- 급간 계산 결과가 0점 미만이 되지 않도록 제한한다.
- 교사는 영역 총점, 급간, 수준별 점수, 수준명, 수준 설명과 관찰 증거를 모두 수정할 수 있다. 모든 점수와 급간은 0~1,000 사이의 정수다.
- 급간을 바꾸면 수준별 점수를 자동 재계산하고 `급간으로 다시 계산`을 제공한다. 교사는 계산 후 개별 수준 점수를 직접 덮어쓸 수 있다.
- 영역별 총점 합은 전체 총점과 정확히 같아야 승인할 수 있다.
- 수준별 점수는 높은 수준에서 낮은 수준으로 엄격하게 감소하고 중복되지 않아야 한다.

### 5.2 루브릭 편집

- 평가영역 추가, 삭제, 복제, 순서 변경
- 성취수준 추가, 삭제, 이름 변경, 순서 변경
- 전체 루브릭 또는 선택한 평가영역만 AI 재생성
- 최대 15개 평가영역
- 각 평가영역에 이름, 설명, 연결 성취기준, 영역 총점, 급간, 허용 수준 점수, 관찰 증거, 과정 또는 결과 구분을 저장
- 과정 평가영역은 `계획 제출`, `중간 산출물`, `피드백 반영`, `수정 이유`, `자기평가` 같은 확인 가능한 자료를 요구
- 지각, 말투, 호감도, 막연한 성실성처럼 성취 증거가 아닌 요소는 자동 생성하지 않음

### 5.3 채점 규칙

- AI는 평가영역마다 하나의 수준을 선택하고 해당 수준에 정의된 점수만 추천한다.
- 추천 결과는 선택 수준, 점수, 답안 직접 근거, 해당 근거가 수준 설명에 부합하는 이유, 다음 성장 피드백, 신뢰도, PDF 근거 위치를 포함한다.
- 교사가 수준을 바꾸면 점수는 그 수준의 허용 점수로 함께 바뀐다.
- 정의되지 않은 중간 점수가 필요하면 먼저 루브릭 점수표를 수정해야 한다.
- 최종 점수는 교사가 원본을 확인한 뒤 확정한다.

## 6. 학생용 수행평가 안내 표지

안내 표지는 전체 문서에 한 장 붙는 표지가 아니라 학생 한 명의 수행평가 묶음 첫 페이지다. 다음 내용을 포함한다.

- 평가명, 교과, 학년·반·번호·이름
- 성취기준과 학생이 이해할 수 있는 전이 목표
- 수행 상황, 역할, 대상, 산출물
- 수행 순서와 제출 조건
- 중간 점검, 피드백, 수정 일정
- 성공 기준과 현재 루브릭 표
- 학생 자기 점검표
- 유의사항과 준비물

표지의 루브릭은 별도 복사본이 아니라 편집 중인 루브릭 데이터를 그대로 사용한다. 영역·점수·설명이 바뀌면 표지도 즉시 갱신한다. 교사는 표지 항목을 편집, 추가, 삭제, 재배열할 수 있다. 표지만 저장하거나 학생별 수행평가 묶음으로 저장할 수 있다.

## 7. 학습지와 평가 문서 편집

- 학습지, 수행과제, 루브릭, 안내 표지, 채점 결과, 세특은 모두 웹에서 직접 수정한다.
- 학습지 생성 요청에는 자유 입력과 문항 유형 선택을 함께 제공한다.
- 문항 유형은 빈칸, 단답형, 서술형, 논술형, 참·거짓, 5지 선다형, 표·그래프 작성, 그림·도표 작성, 실험 기록, 자기평가를 지원한다.
- 교사는 섹션과 문항을 추가, 삭제, 복제, 순서 변경할 수 있다.
- AI가 생성한 문항은 하나 이상의 선택 성취기준과 연결되고 교사는 연결을 수정할 수 있다.
- 교사용 예시 답안과 채점 포인트는 학생용 문서와 분리한다.

## 8. 공용 학생 명단

프로젝트는 한 개의 공용 학생 명단을 사용한다.

```text
Student
├─ id
├─ grade
├─ className
├─ number
└─ name
```

- 교사는 표에서 학생을 직접 추가, 수정, 삭제, 순서 변경할 수 있다.
- 한 프로젝트의 학생은 최대 50명으로 제한하고 제한값을 명단과 업로드 화면에 표시한다.
- Excel 양식을 내려받고 같은 열 구조로 일괄 업로드할 수 있다.
- 양식 열은 `학년`, `반`, `번호`, `이름`만 사용한다.
- Excel 행 순서를 명단 순서로 보존한다.
- 빈 행은 무시하고 필수값 누락, 중복 학번, 잘못된 번호는 행별 오류로 표시한다.
- 명단 변경은 기존 학생 결과를 이름으로 묵시적으로 재연결하지 않고 안정적인 학생 ID로 연결한다.
- Excel 읽기와 양식 생성은 브라우저에서 동적 로드한 `exceljs`로 처리해 명단 파일을 별도 서버에 업로드하지 않는다.

## 9. 합본 PDF와 학생별 페이지 매핑

교사는 학생별 개별 PDF 또는 명단 순서로 스캔한 합본 PDF를 사용할 수 있다.

- 기존 10개 파일 제한을 학생 명단 최대 50명으로 대체한다. 개별 PDF는 학생당 10MB, 합본 PDF는 100MB와 300쪽 이하로 제한한다.
- 합본 PDF는 브라우저에서 기존 `pdf-lib`로 학생별 분리하며 합본 원본을 서버에 보내지 않는다.
- 합본 모드에서 `학생 1명당 답안 페이지 수`를 입력한다. 이 값은 안내 표지를 제외한 답안 페이지 수다.
- `각 학생 묶음 첫 페이지가 수행평가 안내 표지` 체크박스를 제공한다.
- 체크하면 학생당 전체 묶음은 `표지 1쪽 + 답안 N쪽`으로 계산한다.
- 업로드 전 예상 총 페이지와 실제 PDF 페이지가 일치해야 자동 분리를 시작한다.
- 불일치하면 예상값, 실제값, 처음 어긋나는 학생을 보여주고 페이지 수 수정을 안내한다.
- 분리 미리보기에서 각 학생의 표지 범위와 답안 범위를 따로 표시한다.
- 표지는 웹 PDF 뷰어에는 포함하지만 OCR과 자동 채점 입력에서는 제외한다.
- 개별 PDF 모드는 명단 학생과 파일을 직접 연결하고 매핑 누락을 표시한다.

## 10. 웹 PDF 원본 확인

브라우저에서 동적 로드한 `pdfjs-dist` 기반 전용 뷰어를 사용한다. 브라우저 기본 PDF `iframe`이나 서버 이미지 변환을 주 뷰어로 사용하지 않는다.

### 10.1 화면 구성

- 데스크톱은 왼쪽에 원본 PDF, 오른쪽에 OCR·루브릭 채점 결과를 표시한다.
- 모바일은 `원본 답안`, `OCR 결과`, `채점 결과` 탭으로 전환한다.
- 페이지 이동, 페이지 번호 입력, 확대·축소, 회전, 화면 맞춤, 전체화면을 제공한다.
- 학생 전환 시 해당 학생의 첫 답안 페이지로 이동한다.
- 표지 페이지에는 `채점 제외 표지`를 표시한다.

### 10.2 근거 연결

- Upstage 응답에서 본문 외에 페이지, 요소 유형, 좌표, 정규화한 텍스트를 보관한다.
- 채점 근거는 하나 이상의 `sourceRef`로 해당 요소를 가리킨다.
- 교사가 근거를 누르면 해당 페이지로 이동하고 관련 영역을 색상 테두리로 표시한다.
- 근거 위치를 찾지 못하면 텍스트 근거만 보여주고 `원본 위치 연결 안 됨`을 표시한다.
- 수식·그래프·그림 또는 낮은 신뢰도의 근거는 `교사 확인 필요` 배지를 표시한다.

### 10.3 필수 확인

- 학생별 `원본 답안 확인 완료` 체크를 제공한다.
- 현재 루브릭에 대한 채점이 유효하고, 필수 근거가 입력되고, 원본 확인이 완료되어야 최종 승인할 수 있다.
- PDF를 다시 연결하거나 OCR·루브릭·점수를 변경하면 원본 확인과 최종 승인을 취소한다.
- PDF 바이트는 서버나 웹 저장소에 영구 보관하지 않는다. 현재 페이지 수명 동안 Blob URL로만 표시하고 해제 시 폐기한다.
- 새로고침으로 파일이 사라지면 OCR과 임시 결과는 유지하되 `원본 PDF 다시 연결` 전에는 승인할 수 없다.

## 11. Upstage 문서 분석 범위와 안전장치

- 텍스트 중심 답안은 `document-parse`와 강제 OCR을 사용한다.
- 표, 차트, 도표, 그림이 예상되는 수행평가는 교사가 확인 가능한 `시각 답안 분석` 설정을 켜고 사용 가능한 경우 Enhanced 모드를 사용한다.
- Enhanced 사용 가능 여부와 모델명은 환경 설정으로 관리하고, 베타 엔드포인트가 실패하면 일반 모드 결과를 확정 채점에 사용하지 않고 수동 확인 상태로 전환한다.
- 단순 표본 시험에서 Enhanced는 선 그래프 관계와 식물 구조도를 설명했지만 수식의 위첨자, 등호, 인수 일부를 잘못 읽었다. 일반 모드는 식물 그림을 존재하지 않는 원형 차트 값으로 오인했다.
- 따라서 수식의 기호·수치 일치가 점수에 직접 영향을 주는 영역은 자동 확정하지 않는다. 원본 위치와 판독 문자열을 나란히 보여주고 교사가 확인해야 한다.
- 실제 한국 학생 손글씨, 수학 풀이, 과학 도표 표본으로 별도 정확도 벤치마크를 통과하기 전에는 `정확한 자동채점`을 제품 문구로 사용하지 않는다.
- 이 단계에서는 외부 비-Upstage 멀티모달 채점 API를 추가하지 않는다.

## 12. OCR·채점 결과 구조

```text
Submission
├─ studentId, fileName, packetPages, answerPages
├─ extractedText, elements[], ocrMode, pageCount
├─ originalAttached, originalReviewedAt
├─ grading
│  ├─ criteria[]
│  │  ├─ criterionId, selectedLevelId, score
│  │  ├─ evidence, reason, feedback
│  │  ├─ confidence, sourceRefs[]
│  │  └─ teacherConfirmed
│  ├─ totalScore, summary, nextSteps
│  └─ sourceHash
└─ approved
```

채점 API는 승인된 현재 루브릭, 편집된 OCR 원문, 구조화된 문서 요소, 선택 성취기준만 사용한다. 직접 근거와 수준 부합 이유를 분리해서 반환한다. 교사는 점수, 수준, 근거, 이유, 피드백을 모두 수정할 수 있다.

## 13. 기록 생성과 편집

- 세특은 공용 학생 명단과 승인된 최신 채점만 사용한다.
- `전체 다시 생성`, `미생성 학생 생성`, 학생별 `생성`, `다시 생성`을 제공한다.
- 다시 생성 전 기존 문장을 보존하고 새 초안과 비교 후 적용한다.
- 기록 근거에는 연결 성취기준, 수행과제, 성장 또는 수정 증거, 승인된 평가영역 근거를 표시한다.
- 점수만 나열하거나 OCR에 없는 인성·태도를 추정하지 않는다.
- 교사는 내용을 직접 수정, 추가, 삭제, 복사할 수 있다.

## 14. 전역 작업 대기·진행 표시

1초 이상 걸릴 수 있는 생성, 분석, OCR, 채점, 내보내기는 공통 `OperationState`를 사용한다.

```text
OperationState
├─ id, kind, label
├─ phase, phaseLabel
├─ progress, progressKind
├─ completedItems, totalItems
├─ startedAt, estimatedRemainingSeconds
├─ cancelable
└─ status, error
```

### 14.1 단일 작업

- 입력 검증·자료 준비 0~10%
- 업로드 10~20%
- OCR·구조 분석 20~50%
- AI 분석·생성 50~80%
- 스키마 검증·한 차례 보정 80~95%
- 저장·화면 반영 95~100%

Upstage가 세부 진행률을 제공하지 않는 구간은 `예상 진행률`이라고 표시한다. 숫자만 임의로 100%까지 움직이지 않고 현재 단계가 끝날 때 다음 구간으로 이동한다.

### 14.2 학급·묶음 작업

- 완료 학생 수와 전체 학생 수를 실제 진행률의 기본값으로 사용한다.
- 현재 학생과 현재 단계, 성공·실패·대기 수를 함께 표시한다.
- 한 학생의 실패는 전체 작업을 중단하지 않는다.
- 취소하면 진행 중 요청을 중단하고 완료 결과를 유지하며, 실패·미처리 학생만 다시 실행할 수 있다.

### 14.3 예상 시간

- 작업 종류, 모델, PDF 페이지 수, 학생 수별 최근 처리 시간의 이동 평균을 현재 세션에 보관한다.
- 표본이 없으면 보수적인 기본 범위를 사용한다.
- `약 20초 남음`처럼 추정치로 표시하고, 변동이 큰 경우 `약 1~2분` 범위를 사용한다.
- 예상 시간을 넘기면 경과 시간, 완료량, 현재 단계를 보여주며 정상 처리 중임을 알린다.

### 14.4 화면과 접근성

- 배경을 반투명하게 어둡게 하고 중앙의 불투명한 상태 패널에 진행률을 표시한다.
- 진행 중 입력과 버튼을 비활성화해 중복 실행을 막는다.
- 5초 이상 걸릴 수 있는 작업에는 `작업 취소`를 제공하고, 취소해도 Upstage에서 이미 시작된 호출 비용은 발생할 수 있음을 알린다.
- 완료 시 상단 알림과 과하지 않은 완료 효과를 제공한다.
- 모바일은 전체화면 상태 패널을 사용한다.
- `role=progressbar`, `aria-valuenow`, live region, 키보드 포커스, 동작 줄이기 설정을 지원한다.
- 오류가 발생해도 교사 입력과 완료 결과는 보존하고 재시도 대상을 명확히 표시한다.

## 15. 데이터 수명과 개인정보

- 프로젝트 구조화 데이터는 현재 탭의 세션 저장소를 사용한다.
- 원본 PDF와 분리된 학생 PDF 바이트는 영구 저장하지 않는다.
- Blob URL은 학생 자료를 교체하거나 페이지를 떠날 때 즉시 해제한다.
- API 키, PDF 바이트, 원본 응답 전체, 학생 이름이 포함된 요청 본문을 서버 로그에 남기지 않는다.
- Upstage 전송 사실, 처리 목적, 원본 보관 여부를 업로드 전에 알린다.
- `학생 자료 모두 지우기`는 명단을 제외한 PDF 연결, OCR, 채점, 기록을 제거하고 별도의 확인을 받는다.

## 16. 오류 처리

- 전체 총점과 영역 총점 합 불일치, 잘못된 급간, 중복 수준 점수는 필드 옆에서 설명하고 승인을 막는다.
- 성취기준 연결 누락은 연결표에서 표시한다.
- Excel 오류는 행 번호와 열을 표시하고 정상 행을 임의로 가져오지 않는다.
- 합본 PDF 페이지 불일치는 자동 분리를 실행하지 않는다.
- OCR이 비었거나 수식·그림 판독이 불확실하면 점수를 생성하지 않고 원본 확인으로 보낸다.
- PDF 원본이 사라졌으면 기존 OCR을 참고용으로 유지하되 재연결 전 승인하지 않는다.
- 일부 학생 생성 실패 시 성공 결과를 보존하고 실패 학생만 재시도한다.

## 17. 검증 기준

### 17.1 단위·계약 테스트

- 전체 총점, 영역 총점 합, 급간, 수준별 점수 계산과 직접 덮어쓰기
- 2~6수준, 최대 15개 평가영역, 성취기준 완전 연결
- 과정 증거와 결과 증거의 구분 및 인성 추정 금지 프롬프트
- 자유 입력과 학습지 문항 유형별 스키마
- 학생 명단 직접 편집, Excel 내보내기·가져오기·오류 행
- 합본 PDF의 표지 포함·미포함 페이지 매핑
- OCR 요소 좌표 정규화와 sourceRef 무결성
- 정의된 수준 점수 이외의 AI 점수 거부
- 원본 확인 전 승인 거부와 변경 후 승인 취소
- 전체·개별 세특 재생성 시 기존 문장 보존
- OperationState의 단계, 실제 묶음 진행률, 취소, 부분 실패, 예상 시간

### 17.2 통합·E2E

- 백워드 설계 생성부터 루브릭 편집, 표지 갱신, 승인까지 완주
- 학생 명단 Excel 업로드 후 표지 포함 합본 PDF를 학생별로 분리
- 데스크톱 PDF 원본과 채점 패널 동시 확인
- 모바일 원본·OCR·채점 탭 전환
- 채점 근거 클릭 시 페이지 이동과 영역 강조
- 수식 불확실 상태에서 자동 승인 차단
- 원본 확인 후 학생별 승인과 전체 세특 생성·개별 재생성
- 모든 장기 작업에서 진행 패널, 취소, 오류 복구 확인

### 17.3 실제 API·시각 검증

- 비식별 한국 학생 표본을 텍스트, 손글씨, 수식, 과학 그래프, 학생 그림으로 나누어 Standard와 Enhanced를 비교한다.
- 문자 정확도만으로 채점 가능성을 주장하지 않고, 점수에 영향을 주는 핵심 기호와 의미 보존을 별도로 기록한다.
- 데스크톱, 태블릿, 모바일 화면과 PDF 뷰어를 캡처해 가로 넘침, 잘린 표, 가려진 진행창, 포커스 문제를 확인한다.
- 전체 단위 테스트, Playwright, Next.js 빌드, PDF·Excel 산출물 검증을 통과해야 완료로 보고한다.

## 18. 이번 확장의 제외 범위

- 수학 수식과 학생 그림의 무검토 자동 확정

- NEIS 직접 전송
