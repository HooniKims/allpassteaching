# 교사용 수업 지도안 작성 MVP 설계

- 작성일: 2026-07-11
- 상태: 사용자 승인 완료
- 대상: 초등학교·중학교·일반고등학교 교사
- 제품 범위: 올인원 교수·학습·평가·기록 웹앱의 첫 번째 워크플로우

## 1. 목표

교사가 학교급, 학년, 과목, 수업할 개념과 차시 범위를 입력하면 2022 개정 교육과정에 맞는 성취기준과 수업 모형을 선택하고, Upstage Solar가 표준 수업 지도안 초안을 생성하도록 한다. AI는 교육과정 선택을 확정하지 않고 근거 있는 후보를 제시하며, 최종 판단과 수정 권한은 교사에게 둔다.

MVP는 로그인과 서버 저장 없이 실행한다. 교사는 생성 결과를 브라우저에서 편집하고 HWPX, DOCX, PDF 중 원하는 형식으로 내보낼 수 있다.

## 2. 성공 기준

1. 선택한 학교급·학년군·과목 밖의 성취기준이 검색·추천·생성 결과에 포함되지 않는다.
2. 교사는 성취기준을 직접 검색할 수도 있고 AI 추천 후보 3~5개를 비교할 수도 있다.
3. 추천 후보마다 성취기준 코드, 원문, 적합도, 추천 이유가 표시된다.
4. 한 차시와 2~10차시 연속 수업을 모두 생성한다.
5. 연속 수업은 단원 전체 흐름과 차시별 상세 지도안을 함께 제공한다.
6. 수업 모형의 단계가 지도안의 도입·전개·정리 활동에 실질적으로 반영된다.
7. 생성 결과를 브라우저에서 수정·복사하고 HWPX·DOCX·PDF로 내려받을 수 있다.
8. Upstage API 장애나 잘못된 응답이 발생해도 교사의 입력과 선택 상태를 잃지 않는다.
9. 데스크톱과 모바일에서 핵심 작성 흐름을 완료할 수 있고 키보드로 모든 조작이 가능하다.

## 3. 범위

### 포함

- 초등학교, 중학교, 일반고등학교
- 프로젝트 폴더의 2022 개정 교육과정 Markdown 자료
- 학교급·학년군·과목별 성취기준 구조화 및 검색
- AI 성취기준 추천과 추천 근거
- 수업 모형 탐색·추천·직접 선택
- 한 차시 및 연속 차시 지도안 생성
- 브라우저 임시 저장과 새로고침 복구
- 결과 편집, 복사, HWPX·DOCX·PDF 내보내기
- Upstage API 키를 서버 환경 변수로 관리

### 제외

- 특성화고 전문교과
- 교사 계정, 로그인, 권한 관리
- 데이터베이스와 클라우드 저장
- 공동 편집과 공유 링크
- 학교별 사용자 양식 업로드
- 결제와 사용량 관리
- 평가·기록 등 후속 워크플로우

## 4. 사용자 흐름

### 4.1 수업 정보

교사가 다음 값을 입력한다.

- 학교급: 초등학교 / 중학교 / 일반고등학교
- 학년: 선택한 학교급에 해당하는 값만 표시
- 과목: 학교급·학년에 해당하는 값만 표시
- 수업 범위: 한 차시 / 연속 차시
- 차시 수: 한 차시는 1, 연속 차시는 2~10
- 차시당 시간: 학교급 기본값을 제안하되 수정 가능
- 수업할 개념 및 내용
- 학생 특성 또는 지원 필요 사항: 선택 입력

필수 입력이 완료되면 다음 단계로 이동한다. 작성 상태는 브라우저 로컬 저장소에 임시 저장한다.

### 4.2 성취기준

두 가지 진입 방식을 동시에 제공한다.

1. **직접 선택:** 학교급·학년군·과목으로 제한된 목록에서 코드나 본문을 검색하고 복수 선택한다.
2. **AI 추천:** 로컬 검색으로 후보를 좁힌 뒤 Upstage Solar가 수업 개념과의 의미 적합도를 평가한다.

AI는 후보 3~5개에 대해 다음 구조를 반환한다.

- 성취기준 코드
- 성취기준 원문
- 적합도: 높음 / 보통 / 낮음 및 정규화 점수
- 추천 이유
- 수업 내용과 연결되는 핵심 표현

추천 코드가 로컬 데이터에 없거나 현재 학교급·과목 범위를 벗어나면 서버가 제거한다. AI는 자동 선택하지 않으며 교사가 최종 기준을 선택해야 다음 단계로 이동한다.

### 4.3 수업 모형

전체 목록을 탐색할 수 있고, 현재 수업에 적합한 3개 모형을 우선 추천한다. 각 모형은 이름, 적합한 상황, 권장 학교급·교과, 진행 단계, 유의점을 제공한다.

핵심 목록은 다음과 같다.

- 직접 교수
- 개념 학습
- 탐구·발견 학습
- 문제 해결 학습
- 프로젝트 학습
- 협동 학습
- 토의·토론 학습
- 역할놀이·시뮬레이션
- 실험·실습 학습
- 디자인 씽킹
- 거꾸로·블렌디드 학습
- 교과별 특화 모형: 반응 중심, 실천적 문제 해결, 수학적 모델링 등

교사는 추천과 무관하게 전체 목록에서 최종 모형 하나를 선택한다.

### 4.4 지도안 완성

Upstage Solar가 검증 가능한 구조화 JSON으로 지도안을 생성한다. 결과는 다음 순서를 따른다.

1. 수업 개요
2. 성취기준
3. 학습 목표
4. 준비물
5. 수업 모형과 적용 이유
6. 도입·전개·정리
   - 단계
   - 교수 활동
   - 학생 활동
   - 소요 시간
   - 자료 및 유의점
7. 과정중심평가
   - 평가 요소
   - 관찰 또는 산출물
   - 피드백 방법
8. 개별화·지원 전략
9. 수업 후 성찰

연속 차시는 먼저 전체 차시 흐름을 보여주고, 각 차시의 상세 지도안을 접어 보거나 전환할 수 있게 한다. 교사는 텍스트와 표 셀을 직접 편집하고, 원본 생성안으로 되돌릴 수 있다.

## 5. 시스템 구조

```text
교육과정 Markdown
    ↓ 빌드 전 추출·정규화
학교급·학년군·과목별 정적 JSON
    ↓ 강제 필터 + 로컬 검색
성취기준 후보 집합
    ↓ Upstage 의미 적합도 분석
추천 이유가 있는 후보 3~5개
    ↓ 교사 최종 선택
수업 모형 + 차시 설정
    ↓ Upstage 구조화 생성
검증된 지도안 JSON
    ↓ 브라우저 편집
HWPX / DOCX / PDF 내보내기
```

### 5.1 애플리케이션

- Next.js App Router 기반 단일 웹앱
- 단계별 작성 화면과 결과 편집 화면
- API 키를 노출하지 않는 서버 API 라우트
- 브라우저 임시 저장을 위한 버전이 있는 로컬 초안 스키마

### 5.2 교육과정 계층

- 원본 Markdown은 변경하지 않는다.
- 빌드 전 스크립트가 성취기준 코드와 원문을 추출한다.
- 추출 결과는 학교급, 학년군, 과목, 영역, 코드, 본문, 출처 파일을 포함한다.
- 중복 문서는 `manifest.json`의 `duplicate_of`를 따라 제외한다.
- 애플리케이션은 정규화된 JSON만 검색하며 원문 전체를 요청마다 모델에 보내지 않는다.

### 5.3 AI 계층

- 기본 모델은 `solar-pro3`이며 `UPSTAGE_MODEL`로 교체할 수 있게 한다.
- 서버 환경 변수 `UPSTAGE_API_KEY`가 있을 때만 AI 기능을 활성화한다.
- 성취기준 추천과 지도안 생성은 별도 API 계약을 사용한다.
- 모델 응답은 JSON 스키마로 검사하고, 알려지지 않은 성취기준 코드는 거부한다.
- 누락이 있으면 전체를 무조건 다시 만들지 않고 누락된 구조만 한 차례 재요청한다.

### 5.4 내보내기 계층

- 하나의 정규화된 지도안 데이터에서 HWPX·DOCX·PDF를 생성한다.
- 화면 표현과 내보내기 문서가 같은 제목·표·차시 구조를 공유한다.
- 다운로드 전 파일 형식과 포함할 차시를 선택한다.
- 문서 메타데이터에 생성일과 2022 개정 교육과정 기반임을 기록한다.

## 6. 화면 및 디자인

### 6.1 기준 방향

선택된 방향은 **차분한 교사 워크벤치**다. Refero의 Notion 계열 문서 작업공간을 주된 기반으로 하고, Super 스타일의 제한적인 단일 행동색 원칙을 차용한다. 한 레퍼런스를 복제하지 않고 교사의 장시간 문서 작업에 맞게 재구성한다.

### 6.2 레이아웃

- 데스크톱: 왼쪽에 4단계 탐색을 고정하고 오른쪽 작업 영역을 전환
- 모바일: 왼쪽 탐색을 상단 진행 표시와 이전/다음 제어로 축약
- 결과 화면: 지도안 문서가 중심이고 편집·내보내기 도구는 보조 영역에 배치
- 카드 사용은 선택 가능한 성취기준·수업 모형처럼 컨테이너 자체가 상호작용할 때만 허용

### 6.3 디자인 토큰

- 캔버스: 따뜻한 중립색
- 작업 면: 흰색
- 본문: 짙은 차콜
- 보조 텍스트: 대비 기준을 만족하는 중간 회색
- 기본 행동색: 짙은 녹색 하나
- 의미 색상: 성공·주의·오류에만 사용
- 표면: 얇은 1px 경계선 중심, 큰 그림자와 그라데이션 금지
- 모서리: 입력·버튼 6~8px, 상호작용 패널 8~12px
- 모션: 단계 전환과 로딩 상태처럼 상태 변화를 설명할 때만 사용

### 6.4 타이포그래피

- 전체 UI에 Paperlogy v1.001을 로컬 호스팅한다.
- 본문 400, UI 레이블·입력값 500, 버튼·소제목 600, 주요 제목 700을 기본으로 한다.
- `font-display: swap`과 시스템 산세리프 대체 글꼴을 설정한다.
- SIL Open Font License 전문을 자산과 함께 보존한다.
- 한국어 조사가 고립되거나 짧은 구문이 부자연스럽게 줄바꿈되지 않도록 주요 문구를 반응형 화면에서 검사한다.

### 6.5 접근성

- 모든 입력은 명시적 레이블과 도움말을 가진다.
- 오류는 색상만으로 전달하지 않고 필드와 연결된 문장으로 표시한다.
- 키보드 포커스에는 `:focus-visible` 상태를 제공한다.
- 터치 대상은 최소 44px을 목표로 한다.
- 본문과 UI 요소는 WCAG AA 대비 기준을 만족한다.

## 7. 오류 처리와 안전장치

- API 키 없음: 설정 방법을 안내하고 직접 성취기준 검색은 계속 제공
- API 오류·타임아웃: 입력과 선택을 유지하고 다시 시도 제공
- 잘못된 JSON: 스키마 오류를 기록하고 한 차례 복구 요청 후 실패 메시지 표시
- 범위 밖 성취기준: 서버 검증에서 제거하고 사용자가 다시 선택하도록 안내
- 생성 중 이동: 초안을 유지하고 생성 취소 또는 계속 대기 선택 제공
- 차시 시간 불일치: 결과와 내보내기 전에 경고하고 자동 균등 조정 또는 직접 수정 선택 제공
- 내보내기 실패: 편집 내용을 유지하고 다른 형식 다운로드를 계속 허용
- 모든 결과에 AI 초안이며 교사의 확인이 필요하다는 문구 표시

## 9. 환경 변수

`.env.example`은 다음 키를 문서화한다.

```dotenv
UPSTAGE_API_KEY=
UPSTAGE_MODEL=solar-pro3
```

실제 키가 들어 있는 `.env.local`과 기타 `.env` 파일은 Git에서 제외한다.

## 11. 구현 원칙

- 교육과정 필터와 검증은 AI 프롬프트가 아니라 애플리케이션 코드가 강제한다.
- AI 추천과 생성은 교사의 결정을 보조하며 자동 확정하지 않는다.
- 원본 교육과정 문서와 생성된 정적 데이터의 출처 연결을 유지한다.
- 하나의 정규화된 지도안 스키마를 화면, 임시 저장, 문서 내보내기가 공유한다.
- MVP 범위를 넘는 계정·서버 저장·공동 편집을 미리 추상화하지 않는다.
