# 세특 생성 상태 검증

세특 생성 전 서버는 현재 지도안, 승인 수행평가, 학생 명단, 학생별 채점 승인 계보를 하나의 상태 스냅숏으로 묶어 HMAC-SHA256 서명 토큰을 발급한다. 토큰 유효기간은 5분이며 생성 API는 다음 항목이 모두 현재 요청과 일치할 때만 Upstage 모델을 호출한다.

- 지도안과 수행평가 전체 내용의 SHA-256 다이제스트
- 학년·반·번호·이름을 포함한 현재 학생 명단 다이제스트와 학생 ID 목록
- 제출물 ID, 학생 ID, 채점 개정 번호, 채점 원본·승인 토큰을 포함한 승인 계보
- 위 항목 전체로 계산한 프로젝트 개정 다이제스트

한 번 발급된 배치 스냅숏과 이후 생성 요청 사이에서 명단에서 빠지거나 정보가 변경된 학생, 만료된 토큰, 변경된 채점 승인 결과는 모델 호출 전에 `409 stale_context`로 차단한다. 응답은 `Cache-Control: no-store`로 전달한다. 이는 클라이언트가 제시한 스냅숏의 일관성을 검증하는 것이며, 서버가 학교의 최신 명단을 별도로 조회해 삭제 여부를 판정한다는 뜻은 아니다.

## 현재 범위의 잔여 위험

이 버전은 별도 서버 데이터베이스와 사용자 인증 세션을 두지 않는 로컬 우선 MVP다. 권위 있는 서버 최신 상태가 없으므로, 과거에 유효했던 지도안·평가·명단·승인 채점 전체 묶음을 가진 사용자는 발급 API에 그 묶음을 다시 제출해 새 5분 토큰을 받을 수 있다. 즉 5분 제한은 발급된 개별 토큰에만 적용되며, 전체 유효 묶음의 재발급·재사용 자체를 막지 않는다. 전체 상태 서명은 한 배치 안의 변조와 부분 재사용을 차단한다. 실제 최신 명단 강제, 일회성 토큰 폐기, 사용자별 권한 분리는 향후 서버 저장소와 인증을 도입할 때 추가해야 한다.
