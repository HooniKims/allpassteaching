# HWPX 수업 지도안 작성·검수 규칙

## 목적

수업 지도안의 내용을 한컴오피스에서 안정적으로 열고 수정할 수 있게 하며, 표가 지나치게 복잡해 깨지는 문제와 줄글처럼 읽히는 문제를 함께 막는다.

## 출력 형식

### 표준 HWPX

- PDF와 같은 순서로 `수업 개요 → 교수·학습 과정 → 과정중심평가 → 지원 → 성찰 → 후속 학습`을 배치한다.
- 수업 개요는 2열 `항목/내용`, 교수·학습 과정은 7열 `단계/학습 요소/교사 활동/학생 활동/시간/자료·유의점/비고`, 과정중심평가는 4열 표로 만든다. 지원·성찰·후속 학습은 테두리가 있는 1열 표로 만든다.
- A4 용지의 좌우 여백은 PDF와 같은 약 48pt인 `4800 HWPUNIT`으로 두고, 표 전체 너비는 `49928 HWPUNIT`으로 고정한다.
- PDF의 열 비율을 그대로 반영해 수업 개요는 `8200/41728`, 과정은 `3600/6000/12000/12000/3600/7200/5528`, 평가는 `7600/7600/9400/25328`로 고정한다.
- HOP에서 한 셀의 여러 독립 문단이 같은 세로 위치에 겹치는 문제를 막기 위해, 모든 표 셀은 문단 하나만 사용한다. 여러 성취기준·활동·수준별 피드백은 그 문단 안의 명시적 줄바꿈으로 구분한다.
- 한 행의 예상 높이가 `30000 HWPUNIT`를 넘지 않도록 셀 내용을 최대 18줄 단위의 이어지는 행으로 자동 분할한다. 첫 행에만 단계·학습 요소·시간·항목명을 표시하고 이어지는 행의 식별 셀은 비운다.
- HOP처럼 한 표 전체를 자동으로 다음 쪽에 넘기지 못하는 뷰어에서도 잘리지 않도록 표 높이를 최대 `50000 HWPUNIT`인 여러 표 조각으로 나눈다. 각 조각에는 열 머리글과 `(계속)` 제목을 반복하고, 페이지의 남은 높이를 계산해 명시적 쪽 나눔을 넣는다.
- `일시`부터 `수업 모형`까지의 수업 정보 값은 가운데 정렬하고, 성취기준·학습 목표·핵심 질문·준비물은 왼쪽 정렬한다.

### 간편 HWPX

- 수업 개요, 교수·학습 과정, 과정중심평가, 지원·성찰을 차시마다 **4개의 2열 표**로 만든다.
- 왼쪽 열은 항목명, 오른쪽 열은 내용이며 열 너비는 `8504 + 34016 = 42520 HWPUNIT`으로 고정한다.
- `colSpan`과 `rowSpan`은 모두 1로 유지한다. 다열 표, 중첩 표, 부동 표, 절대 위치 도형은 쓰지 않는다.
- 표는 글자처럼 배치하고(`treatAsChar=1`), 본문과 함께 흐르게 하며(`flowWithText=1`), 겹침을 허용하지 않는다(`allowOverlap=0`).
- 표의 최소 행 높이, 셀 여백, 자동 줄 수 계산을 적용한다. 내용이 길면 칸을 억지로 줄이지 않고 다음 쪽으로 이어지게 한다.
- 교수·학습 과정에서는 한 셀에 여러 활동 문단을 몰아넣지 않는다. 단계 요약과 교사 활동·주요 발문·학생 활동·예상 반응·자료·지원의 각 항목을 독립된 2열 행으로 만든다.
- 과정 표의 오른쪽 셀은 항목 하나당 본문 문단 하나만 두고 10pt 본문 스타일을 사용한다. 여러 활동이 있으면 같은 항목명의 행을 추가한다.

### 수행평가지·루브릭 HWPX

- `학생 안내문`, `제출용 수행평가지`, `안내문과 수행평가지 전체본`을 서로 다른 파일 종류로 생성한다. 제출용 파일에는 학생 안내문을 포함하지 않는다.
- 제출용 수행평가지는 PDF와 같은 좌우 `4800 HWPUNIT` 여백과 `49928 HWPUNIT` 본문 폭을 사용한다. PDF 렌더러가 새 쪽에서 시작한 문항 앞에는 HWPX에도 명시적 쪽 나눔을 넣어 두 형식의 쪽 수를 맞춘다.
- 작성 안내는 연한 배경의 전체 폭 표로, 표·그래프 응답지는 전체 폭 4행 표로, 서술형 응답지는 교사가 정한 줄 수만큼의 전체 폭 행으로 만든다. PDF에 없는 임의의 열 이름이나 기록 양식을 추가하지 않는다.
- 루브릭은 두 열로 수준 설명을 이어 쓰지 않는다. 첫 열은 평가영역, 나머지 열은 교사가 정한 각 성취수준으로 구성한다.
- 평가영역별 총점의 합은 문서의 전체 총점과 같아야 하며, 각 수준 셀의 첫 줄에 해당 수준 점수를 표시한다.
- 모든 루브릭 셀은 문단 하나만 사용하고, 점수와 수행 기술은 같은 문단 안의 줄바꿈으로 구분한다.
- 장문 셀은 최대 18줄 단위의 이어지는 행으로 나누고, 한 표의 예상 높이가 `60000 HWPUNIT`를 넘기 전에 새 표를 시작한다.
- 새 표 앞에는 명시적 쪽 나눔을 넣고 `평가영역`과 모든 성취수준 머리글을 반복한다. HOP에서 문서 쪽 수가 실제 표 조각 수에 맞게 계산되는지 확인한다.

## 수업 지도안 내용 규칙

- 제목, 차시, 수업 정보, 성취기준, 학습 목표, 핵심 질문, 준비물을 빠뜨리지 않는다.
- 교수·학습 과정은 도입·전개·정리의 단계 요약 행을 먼저 만들고, 교사 활동·주요 발문·학생 활동·예상 학생 반응·자료 및 지원을 각각 별도 행으로 구분한다.
- 과정중심평가는 평가 요소·방법, 관찰 증거, 피드백, 수준별 피드백을 한 평가 행에 함께 둔다.
- 지원 전략, 수업 후 성찰, 후속 학습은 마지막 표에 남긴다.
- 값이 빈 경우에도 표 구조는 유지하되, 빈 셀은 빈 문단으로 생성한다.
- 날짜는 `YYYY. M. D.`, 교시는 `N교시`로 한 번만 출력한다. 입력이 `N교시`여도 중복 접미사를 붙이지 않는다.

## OWPML 작성 규칙

- `section0.xml`의 첫 문단에는 `secPr`와 `colPr`을 유지한다.
- ZIP 첫 엔트리는 압축하지 않은 `mimetype`이어야 하며 값은 `application/hwp+zip`이다.
- `hp`, `hs`, `hh`, `hc` 네임스페이스와 `header.xml`의 스타일 참조를 보존한다.
- `charPrIDRef`, `paraPrIDRef`, `borderFillIDRef`, `itemCnt`, 문단·표 ID의 정합성을 검사한다.
- Paperlogy 스타일을 사용하되, 표 머리글·본문·제목의 글자 및 문단 스타일을 섞지 않는다.
- 새 내용이나 수정된 문단에는 `hp:linesegarray`를 남기지 않는다. 한컴이 현재 내용으로 줄 배치를 다시 계산하게 한다.
- HOP의 `비표준 줄 정보` 안내는 제거한 줄 배치 캐시를 뷰어가 다시 계산하겠다는 뜻이다. `그대로 열기`와 `자동 보정`을 각각 확인하되, 어느 쪽에서도 명시적 쪽 나눔과 문항 표가 잘리거나 겹치면 안 된다.
- `hp:t` 안의 줄바꿈·탭 같은 자식 컨트롤은 삭제하거나 pretty-print 결과로 다시 패키징하지 않는다.

## 생성 및 검수 게이트

1. 생성 후 ZIP 구성, XML 문법, mimetype 위치를 검사한다.
2. 네임스페이스·스타일 개수·ID 참조를 점검하고, 줄 배치 캐시를 제거한다.
3. 표별 열 수·열 너비 합계·셀 주소·병합 여부·행 높이를 자동 검사한다.
4. 표 안의 필수 수업 정보와 성취기준·활동·평가·성찰 문구가 모두 있는지 검사한다.
5. 기존 HWPX 양식을 교사가 제공하면 새로 구조를 만들지 않는다. 슬롯을 추출해 셀과 문단의 텍스트만 바꾸고, 구조·글자 예산·쪽수 드리프트를 비교한다.
6. 한컴오피스 또는 HWPX 뷰어가 있는 환경에서는 최종 파일을 열어 실제 페이지 나눔, 글꼴 대체, 표 잘림, 셀 안 문단 겹침을 확인한다. 자동 검증만으로 실제 렌더링까지 통과했다고 주장하지 않는다.

## 적용 도구

- 기본 생성: 프로젝트의 OWPML 생성기
- 구조 검사: `validate.py`
- 레이아웃 위험 검사: `fix_namespaces.py`, `finalize_hwpx.py --strip-linesegarray --layout`, `validate.py --layout`
- 기존 양식 편집: `hwpx_slots.py`, `edit_hwpx.py`, `page_guard.py`, `content_guard.py`

이 규칙은 [Canine89/hwpxskill](https://github.com/Canine89/hwpxskill)의 XML 보존·레이아웃 검수 원칙과 프로젝트의 HWPX 생성·회귀 테스트를 결합해 정한다.
